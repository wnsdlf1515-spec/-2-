# 다온시 실시간 수업 모드

기존 개인용 게임과 별도의 **Node 서버**에서 교사 대시보드와 조별 게임을 함께 제공합니다. GitHub Pages는 이 서버를 실행하지 못합니다. 공개 서버 주소에서 교사·학생이 같이 접속해야 하며 기존 Pages에서 진행한 게임이 자동 집계되는 방식은 아닙니다.

## 구현

- 교사 생성 암호로 수업방 생성 → 8자리 참가 코드 공유 → 조 이름으로 참가.
- 최대20개 조, 권장20명/2인1조/10대. 조당 조작 기기 하나. 여러 학생이 한 도시를 동시에 공동 편집하는 기능은 아님.
- 교사가 초기 시나리오·목표·시드를 정하고 수업 시작, 일시정지, 재개, 종료, 삭제.
- 교사는 연결 조·완료 조·현재 지표 표와 인구/예산/돌봄/의료/취업 추세를 실시간 확인.
- 차트는 공통 게임 턴 기준. 0턴은 초기 상태,1~8턴은 결산. 진행하지 않은 턴을 추정하지 않음. 표는 현재 상태이므로 턴 중 투자비가 먼저 반영될 수 있음.
- 전체 돌봄은 이용 합÷수요 합, 의료는 인구 가중. 인구 증가만으로 순위를 매기지 않음.
- 선택 기록을 서버의 기존 게임 엔진이 다시 계산. 임의의 인구/예산 수치는 반영하지 않음.
- 선택마다 SQLite 저장, 재연결/새로고침/서버 재시작 복구, 중복 전송 멱등 처리, 두 탭의 충돌 시 최신 상태 복원.
- 교사 JSON/CSV 내보내기. 실명·학생 계정·채팅 없음. 데이터와 참가 권한은7일 보관 후 삭제.

## 첫 수업

1. 교사가 서버 주소에 접속하여 생성 암호, 시나리오·목표·시드를 입력한다.
2. 학생들에게 **같은 서버 주소와 참가 코드**를 공유한다. 실명 대신1조~10조를 사용한다.
3. 각 조는 한 기기로 참가한다. 교사는 참가 현황을 확인한 뒤 수업 시작을 누른다.
4. 학생들은 기존 게임처럼 정책/지역 선택과 턴 진행. 별도의 제출 버튼은 없다.
5. 중간 설명 때 전체 일시정지, 설명 뒤 운영 재개. 지표 선택기로 차트를 바꾼다.
6. 8턴 결과를 비교하고 JSON/CSV를 내려받는다. 수업 종료는 되돌릴 수 없고, 삭제는 서버 기록까지 지운다.

새로고침은 안전하다. ‘참가 정보 지우기’는 이 기기의 접근 권한을 제거하므로 수업 중에는 사용하지 않는다. 브라우저 데이터가 삭제되면 기존 조를 복구할 별도 계정/인증 절차는 현재 없다. 개인 JSON은 보관용이며 수업방 재시작/파일 가져오기는 막혀 있다. 다른 조건으로 다시 하려면 기록을 내보내고 새로운 수업방을 만든다.

## 교사 PC에서 가장 쉽게 시작하기

1. 전체 ZIP을 다운로드하고 **압축을 모두 푼다**. `classroom`과 `city-stage6` 폴더를 함께 유지한다.
2. 교사 PC에 [Node.js 24 이상](https://nodejs.org/)을 한 번 설치한다. 학생 기기에는 설치가 필요 없다.
3. `classroom/수업서버-시작.cmd`를 두 번 클릭한다(Windows).
4. 생성 암호를8자 이상 입력하고 Enter. 입력 문자는 표시하지 않으며 암호를 파일에 저장하지 않는다.
5. 창에 표시된 교사용 주소를 교사 PC 브라우저에서 연다. 수업방 생성에 같은 암호를 입력한다.
6. 학생에게는 **학생 접속 후보 주소 중 학교망 IP 주소**와 화면의 참가 코드를 전달한다. 여러 주소가 표시되면 학생 기기1대로 먼저 확인한다.
7. 수업 동안 서버 창을 열고 PC 절전/네트워크 변경을 피한다. 종료는 Ctrl+C.

Windows 방화벽이나 학교 AP의 기기 격리로 연결되지 않으면 학교 담당자에게 같은 내부망에서 교사 PC의 TCP4190 접속 허용 여부를 확인한다. 임의로 공용 인터넷에 포트를 열 필요는 없다. 다른 망의 기기는 참가할 수 없다.

Mac/Linux는 압축을 푼 `classroom` 폴더에서 `node start-local.cjs`를 실행한다. 실행 도구와 공통 서버는 Linux에서 검증했고 Windows 배치 파일 자체는 이 환경에서 실행하지 못했다.

서버 기록은 `classroom/data/`에 생긴다. 업데이트 전 서버를 정상 종료하고 이 폴더를 보관한다. 생성 암호는 새 방을 만들 때만 쓰며, 기존 방 접근은 해당 브라우저의 참가 정보로 복원된다.

## 개발용 직접 실행

Node24 이상. 실행용 외부 npm 의존성은 없다. 저장소 루트에서:

```sh
node classroom/tools/build.cjs
# Bash: 암호를 화면이나 명령 기록에 남기지 않고 입력
read -rsp '교사용 생성 암호: ' CLASSROOM_CREATE_KEY
export CLASSROOM_CREATE_KEY
node classroom/server.cjs
```

기본 포트4190. 브라우저에서 교사 PC의 내부망 주소와 포트4190으로 접속한다. 다른 학생 기기는 localhost가 아닌 교사 PC의 내부망 IP를 사용한다. 학교 Wi-Fi의 기기 간 통신 차단/방화벽 여부는 학교 환경에서 확인해야 한다. 교사 PC를 끄면 접속이 중단된다.

개발용으로만 `CLASSROOM_DEV=1 node classroom/server.cjs`를 쓸 수 있다. 이때 생성 암호가 생략되므로 공개 서버에서는 사용하지 않는다.

## 공개 서버 배포

저장소 루트에서 Dockerfile을 빌드한다:

```sh
docker build -f classroom/Dockerfile -t daon-classroom .
docker volume create daon-classroom-data
docker run --name daon-classroom -p 4190:4190 \
  --env CLASSROOM_CREATE_KEY \
  --mount source=daon-classroom-data,target=/app/data \
  daon-classroom
```

HTTPS 종단을 제공하는 호스팅/리버스 프록시 뒤에서 운영한다. 프록시에서는 SSE 버퍼링을 끄고 연결 제한 시간을15초 heartbeat보다 길게 둔다. 역방향 프록시의 Host와 X-Forwarded-Proto=https를 전달한다.

Render용 Blueprint는 `classroom/render.yaml`. 저장소를 연결하고 Blueprint Path를 이 파일로 지정한다. **starter 웹 서비스와 영구 디스크는 유료일 수 있으므로 제공자의 표시 가격을 확인한 뒤 배포를 승인한다. 이 작업에서는 서비스 구매·계정 생성·유료 배포를 하지 않았다.** 생성되는 CLASSROOM_CREATE_KEY는 호스팅 환경 설정에서 교사만 확인하며 채팅이나 학생에게 공유하지 않는다. 학생에게는 참가 코드만 공유한다.

필수 환경 변수:

| 이름 | 의미 |
|---|---|
| CLASSROOM_CREATE_KEY | 교사용 수업방 생성 암호. 공개 운영 필수 |
| DATA_FILE | SQLite 파일. 기본 classroom/data/classroom.sqlite; 컨테이너는 /app/data/classroom.sqlite |
| PORT | 기본4190; 호스팅 제공 값 사용 |

영구 디스크 없이 배포하면 재배포/인스턴스 교체 시 수업 기록이 사라질 수 있다. 이 버전은 **단일 서버 인스턴스+로컬 SQLite** 구성이다. 여러 복제본으로 자동 확장하지 않는다. `/healthz`는 실행 확인 엔드포인트다. 배포 후 교사1명·학생2개 브라우저로 생성→참가→정책→차트→새로고침을 공개 HTTPS 주소에서 확인한다.

## 검증

```sh
node --test classroom/tests/server.test.cjs
node classroom/tests/browser.cjs
```

브라우저 검증에는 Playwright1.62.1과 `/usr/bin/chromium`이 필요하다. 테스트는 전용 임시 DB/임의 포트를 사용하며 운영 데이터에 접근하지 않는다. `artifacts/`에 표본 결과와 화면을 저장한다. 상세 범위는 [VALIDATION.md](VALIDATION.md).

## 남은 범위

- 실제 학교20대 Wi-Fi, 인터넷 지연/장시간 수업, 공개 HTTPS 환경 검증은 별도 필요.
- 동일 조 복수 조작자의 협업/권한 분담, 교사 계정/여러 수업방 목록, 계정 기반 복구는 없음.
- 게임의 도트와 인구·정책 규칙은6단계와 동일하며 실제 정책 예측 모형이 아님.
- 무료 호스팅의 휴면이나 임시 저장소를 전제로 수업의 안정성을 보장하지 않음.

## Windows에서 MODULE_NOT_FOUND가 나올 때

경로가 `AppData\Local\Temp\...zip...`이고 `start-local.cjs`를 찾지 못한다면 ZIP 안에서 CMD만 실행했을 가능성이 큽니다. Node.js를 다시 설치할 필요는 없습니다. ZIP을 우클릭해 **모두 압축 풀기**를 실행한 뒤, 풀린 `daon-classroom/classroom/수업서버-시작.cmd`를 여세요. 같은 폴더에 `start-local.cjs`와 `server.cjs`가 보여야 하며, 상위 폴더에는 `city-stage6`도 있어야 합니다. CMD만 다른 폴더로 옮기지 마세요.
